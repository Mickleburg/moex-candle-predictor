# Источник новостей V2: e-disclosure.ru — валидированный механизм доступа

> Статус: спайк-проверка пройдена (2026-06-15). Источник выбран пользователем: **e-disclosure
> через Playwright** (после того как SKRIN не покрыл голубые фишки, а официальный API оказался
> платным). Данные реально достаются, no-lookahead соблюдаем по `pubDate`.

## Почему e-disclosure и почему Playwright

- В РФ каждый эмитент раскрывается через ОДИН авторизованный центр. ~90% листингованных бумаг
  раскрываются через **Интерфакс-ЦРКИ (e-disclosure.ru)**, остальные приходят туда от других
  агентств → покрытие почти полное. **SKRIN не содержит SBER/GAZP/LKOH** (отпал).
- e-disclosure за анти-бот **WAF ServicePipe**: обычный `requests`/`Invoke-WebRequest` получает
  JS-челлендж (даже при HTTP 200). **Playwright (Chromium) проходит челлендж**; после загрузки
  страницы — звать API **через in-page `fetch`** (APIRequestContext по-прежнему получает челлендж).
- Официальный REST API («Шлюз Раскрытие», Swagger, JSON) существует, но **платный**: 16 180–27 000
  ₽/мес, мин. 3 мес, фикс IP, архив глубже 01.07.2020 +50%. Для ресерча до доказанного эджа не берём.

## Рабочий эндпоинт (публичный сайт)

`POST https://www.e-disclosure.ru/api/search/sevents` — вызывать in-page `fetch` после загрузки
`/poisk-po-soobshheniyam` (WAF-cookie уже в контексте). Тело — `application/x-www-form-urlencoded`:

```
eventTypeTerm=&radView=0&dateStart=DD.MM.YYYY&dateFinish=DD.MM.YYYY
&textfieldEvent=&radReg=FederalDistricts
&districtsCheckboxGroup=-1&regionsCheckboxGroup=-1&branchesCheckboxGroup=-1
&textfieldCompany=<имя>&query=<имя>          # фильтр по компании (серверный)
&lastPageSize=<N>&lastPageNumber=<page>&queryEvent=
```

Ответ JSON: `{"foundEventsList":[ {...} ]}`. Поля события:

| поле | смысл | для контракта |
|------|-------|---------------|
| `pubDate` | **время ПУБЛИКАЦИИ** (ISO, мск) | → `sources[].published_at`; **no-lookahead: фильтр `pubDate <= as_of`** |
| `eventDate` | дата самого события | НЕ использовать для no-lookahead |
| `eventName` | тип/заголовок раскрытия | → сырьё для `features.event_type` |
| `companyID`, `companyName` | эмитент | маппинг тикер↔эмитент |
| `pseudoGUID` | ключ к полному тексту сообщения | догрузка тела для LLM |
| `agency` | агентство-источник (ИНТЕРФАКС) | метаданные `sources[].source` |
| `isCorrectedByAnotherEvent` | сообщение скорректировано позднее | флаг качества |

Подтверждено: `dateStart/dateFinish` принимают произвольный исторический диапазон; **июль 2020
отдаёт полную ленту** (история до 2020 есть). Фильтр `query` — серверный, по подстроке имени.

Справочник типов: `GET /api/data/sevent-types` → `[{id,name}]` (полная таксономия существенных
фактов; основа для нормализации `event_type`).

## Извлечение каверзов сервера (учтено в экстракторе)

- **Кап ~1200 результатов на запрос**: сервер отдаёт максимум ~12 страниц по 100, обрезая САМЫЕ
  СТАРЫЕ. Годовые окна теряли половину истории. Решение — **адаптивное дробление окна пополам по
  датам, пока сырой объём ≥ 1200** (`extract_ticker` рекурсивно). Гарантирует полноту.
- **`dateFinish` в будущем → пустой ответ**: дату окончания клампим к `today`.
- API фильтрует только по подстроке имени (`query`), фильтра по `companyId` НЕТ → отбираем нужный
  `companyID` клиентски. WAF-cookie освежаем перед каждым тикером (длинный прогон не протухает).

## Дивидендная no-lookahead сертификация (H9 run-up, 2026-06-17)

ML-блок нашёл робастный эдж — дивидендный пред-ex run-up (вход ~12 ТД до ex-даты). Чтобы
сертифицировать его как no-lookahead, нужна дата ПЕРВОГО публичного объявления дивиденда ≤ record−12ТД.

Цепочка раскрытий в РФ: **СД рекомендует дивиденд + созывает ОСА** (один совет) → **ОСА утверждает**
→ record date ~10-20 дн. спустя. Сумма дивиденда — в ТЕЛЕ сообщения (в parquet нет), но классы
ЗАГОЛОВКОВ однозначно пинят цепочку:
- `board_reco_date` = самое раннее публичное раскрытие рекомендующего совета = ранний из
  «Решения совета директоров» и «Созыв общего собрания акционеров», спаренных по дате (один совет);
  плюс явный пресс-релиз «…РЕКОМЕНДАЦИИ ПО ВЫПЛАТЕ ДИВИДЕНДОВ» где есть (PLZL/ROSN — gold standard).
- `agm_date` = «Решения общих собраний акционеров».
- Созыв должен опережать решение ОСА на ≥18 дн (легальный срок уведомления) — иначе это созыв
  ДРУГОГО (будущего) собрания (ловушка у NLMK/PLZL с перекрывающимися квартальными дивидендами).

Сборщик: `llm/scripts/build_dividend_announcements.py` → `data/news/dividend_announcements.csv`
(колонки: ticker, record_date, board_reco_date, agm_date, source_url, confidence, notes; даты ISO;
record_date дословно из `data/raw/dividends.csv` для join). No-lookahead — только по `pubDate`.

**Результат (134 события, 16 тикеров, record 2020-2025):** покрытие 129/134 (96%);
**no-lookahead тест board_reco ≤ record−12ТД: 129/129 PASS, 0 нарушений**; медиана зазора reco→record
= 37 торг. дн (мин 18). Confidence: 122 high / 7 medium. 5 без матча: 4 — record в начале янв-2020
(рекомендация в 2019, до floor данных 2020-01-01); 1 (NLMK 2023-01-11) — пост-2022 NLMK раскрывал
через дженерик «существенное влияние», отдельного титула СД/созыва нет (ОСА 2022-12-31 есть, но
сам ~7 ТД до record — отдельный red flag для этого имени). Эти 5 — на ручной разбор/исключение ML.
