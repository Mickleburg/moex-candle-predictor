# Архитектура V2 — кросс-секция + ранняя ML/LLM фьюжн

> Статус: целевая архитектура (после провала направленной 1H-постановки, 2026-06-15).
> Обоснование пивота: `ml/docs/PATHS_FORWARD_2026-06-15.md`, вердикт:
> `ml/docs/research/DIRECTIONAL_1H_VERDICT_2026-06-15.md`.

## Зачем меняем

**Старая архитектура (late fusion):**
```
backend → [candle_batch] → ml  → [ml_prediction]  ─┐
                         → llm → [llm_analysis]   ─┤→ aggregator (веса 0.75/0.25) → ...
```
Два НЕЗАВИСИМЫХ слабых сигнала buy/hold/sell, смешиваются поздно фиксированными весами. Проблемы,
которые это создало:
- ML-сигнал (направление 1H одной бумаги) оказался шумом (win~40%, доказано 3 проверками).
- Позднее слияние теряет взаимодействие модальностей («бычьи технички И позитивная новость» сильнее
  суммы, но из готовых вероятностей не извлекается).
- Абсолютное направление ловит полный удар смены рыночного режима (бета).

## Целевая архитектура V2

```
                         ┌─ backend (свечи) ──────────────┐
ДАННЫЕ                   ├─ market context (индексы/фьючи/FX) ┤
                         └─ news ingestion (лента новостей) ──┘
                                        │
ПРИЗНАКИ        ┌─ quant features (цена/технички, кросс-секционные)
               └─ LLM news features (sentiment, событие, затронутые тикеры, impact, эмбеддинги)
                                        │  ← РАННЯЯ ФЬЮЖН (на уровне признаков)
РЕШЕНИЕ         одна кросс-секционная модель: ранжирует тикеры по ОТНОСИТЕЛЬНОЙ силе
                                        │
ПОРТФЕЛЬ        risk_manager: long top-k / short bottom-k, маркет-нейтрально, лимиты/сайзинг
                                        │
ИСПОЛНЕНИЕ      execution
```

### Ключевые изменения ролей блоков

| Блок | Было | Стало (V2) |
|------|------|-----------|
| **llm** | независимый предсказатель buy/hold/sell | **извлекатель новостных ПРИЗНАКОВ** (NLP): sentiment, тип события, затронутые тикеры, оценка влияния, эмбеддинги. НЕ принимает торговое решение |
| **ml** | направление 1H одной бумаги | **кросс-секционная модель**: ранжирует много тикеров по относительной доходности (тикер − индекс/сектор), на объединённых `[цена ⊕ новости]` фичах |
| **aggregator** | late fusion 0.75/0.25 | (опц.) сводит признаки/скоры; основная фьюжн теперь РАННЯЯ, внутри решающей модели |
| **risk_manager** | пер-тикер допуск | **портфельная конструкция** long/short top-bottom, маркет-нейтрал, лимиты, сайзинг |
| **aggregator** | late fusion 0.75/0.25 | **удалён** (фьюжн теперь ранняя, внутри решающей модели) |
| backend | Go HTTP, свечи | **переписывается на Python**, + источник market context. Go-версия удалена 2026-06-15 |

> **Стек:** весь проект — Python. Go-бэкенд удалён (2026-06-15), включая его внутреннюю
> late-fusion-агрегацию. Блок `aggregator/` тоже удалён.

### Изменения контрактов (черновик — детализировать)

- `llm_analysis`: вместо `{buy,hold,sell}` → **новостные фичи** по тикеру/моменту:
  `{sentiment, event_type, affected_tickers[], impact_score, embedding[], as_of, source}`.
- Новый контракт `feature_bundle` (или расширение): объединённые `[quant_features ⊕ news_features]`
  на вход решающей модели.
- `aggregated_signal`: вместо одного buy/hold/sell → **кросс-секционный скор/ранг** по тикерам
  (relative strength), который risk_manager превращает в long/short портфель.

## Что переиспользуем (не выбрасываем)

Per-ticker роутер, MarketContextProvider (self-fetch индексов/фьючерсов), загрузчики
свечей/индексов/фьючерсов, гигиена tz, и — главное — **метод deployment-симуляции** как
единственный валидный способ оценки.

## Принципы

1. **Маркет-нейтрал**: предсказываем относительное, не абсолютное (снимаем бету).
2. **Ранняя фьюжн**: одна модель над всеми модальностями, не позднее усреднение.
3. **LLM = NLP-фичи, квант = решение.**
4. **Валидация только deployment-симуляцией** на свежем forward; робастность важнее пикового Sharpe.
5. `is_production=false` до честного forward-гейта + sign-off.

## Открытые проектные решения (обсудить)

- Точный относительный таргет (vs индекс? vs сектор? cross-sectional rank?).
- Где физически живёт решающая модель — ml-блок или новый fusion-блок.
- Формат и частота новостных фич; маппинг новость→тикер.
- Нужен ли aggregator вообще при ранней фьюжн, или он становится тонким сборщиком.
