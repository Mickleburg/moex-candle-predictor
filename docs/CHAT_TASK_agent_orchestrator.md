## Контекст проекта
MOEX trading agent, ветка `change-strategy`, архитектура V3 (`docs/ARCHITECTURE_V3.md`). Цель —
**автономный агент на VDS** вокруг H9 (дивидендный run-up). Зонтичный план + суточный цикл —
`docs/VDS_AUTONOMOUS_PLAN.md` (прочитай целиком — это твоя спецификация). `agent/` сейчас скаффолд, и
**его README устарел** (описывает мёртвый V2-кросс-секшн — перепиши под V3-сливы). Инфраструктуры нет
(нет Dockerfile, top-level requirements, scheduler) — её строишь ты.

## Что значит «автономный» (требование пользователя)
Агент сам: (1) собирает данные · (2) мониторит · (3) реагирует на изменения · (4) обновляет базу
знаний · (5) управляет портфелем. Ты оркеструешь всё это в суточный цикл и держишь его живым на VDS.

## Что уже готово (твои входы — вызывай, не реализуй заново)
- **ML-слив:** `ml/src/service/dividend_sleeve.py::build_sleeve_signal(panel, calendar, as_of)` →
  JSON `sleeve_signal` (лонги + hedge_recommendation). Монитор: `ml/scripts/dividend_sleeve_monitor.py`.
- **risk_manager-комбинатор:** `risk_manager/scripts/demo_combine_h9.py` (потребляет слив → `risk_book`,
  vol-target × режимный гейт H5 × лимиты × сектор-хедж). Контракты `sleeve_signal`/`risk_book`.
- **backend/data** (параллельный чат): scheduled ingest + integrity-гейт + **торговый календарь MOEX**
  (RU-праздники) — импортируй календарь отсюда, единый на проект.
- **execution** (параллельный чат): брокер-адаптер dry-run/paper/live + дисциплина −12/−2 + kill-switch.
- **LLM/news** (ongoing чат): держит `data/news/dividend_calendar_upcoming.csv` свежим.
- Контракты в `contracts/`, валидатор `scripts/validate_contracts.py`. Риск-политика —
  `config/ml_risk_policy.json` (устаревшая V1 — при необходимости заведи V3-конфиг рядом).

## Задача A — Оркестратор (`agent/`)
1. **Суточный state-machine цикл** (см. таблицу EOD в плане): ingest → integrity-гейт (HALT на фейле)
   → ML-слив(as_of) → risk_manager-комбинатор → execution(paper) → персист → алерт. Плюс pre-open
   проверка (гэпы/халты, подтверждение ордеров, kill-switch).
2. **State-store:** текущие позиции, открытые ордера, **P&L-атрибуция ПО СЛИВАМ** (слив без эджа на
   forward → его вклад виден и зануляется). Файлы/SQLite — реши; идемпотентность и восстановление
   после рестарта обязательны.
3. **Реакция (3):** на HALT данных — не торговать; на режимный гейт H5 — следовать срезу гросса; на
   новую ex-дату из фида — плановый вход; kill-switch доступен.
4. Перепиши `agent/README.md` под V3 (сейчас V2-кросс-секшн — неверно).

## Задача B — Инфра/деплой на VDS (можно вынести в отдельный чат, если перегруз)
1. **Воспроизводимое Linux-окружение:** Dockerfile/compose ИЛИ venv+requirements верхнего уровня
   (текущее окружение — Windows venv py3.14; VDS — Ubuntu LTS Linux). Зафиксируй pin-версии.
2. **Scheduler:** EOD (~19:05 МСК) + pre-open (~09:30 МСК) триггеры только по торговым дням
   (systemd-timer / APScheduler / cron). TZ=Europe/Moscow.
3. **Супервизор процессов** (systemd/docker-restart), логирование (структурные логи + ротация),
   **бэкапы** state-store и data.
4. **Мониторинг/алерты:** канал (Telegram-бот рекоменд. / email) + health-checks + **dead-man's-switch**
   (если цикл не отработал — алерт). Дайджест: входы/выходы, статус гейта, P&L, data-фейлы.
5. **Секреты:** `.env`/секрет-стор (брокер-ключи, токен бота). `.env.example` дополнить. Никогда в git.

## Приёмка
- Полный цикл проходит end-to-end на МОКах блоков (или их CLI) в paper-режиме, идемпотентно,
  переживает рестарт (state восстанавливается).
- Integrity-HALT реально блокирует торговлю; режимный гейт срезает гросс; kill-switch останавливает.
- На VDS: окружение поднимается из чистого клона одной командой; scheduler срабатывает по расписанию;
  алерт приходит в канал; dead-man's-switch ловит пропущенный цикл.
- `is_production=false` сквозь артефакты; `python -m pytest ml/test_smoke.py` зелёный; контракты валидны.
