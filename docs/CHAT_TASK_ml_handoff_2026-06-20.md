# Контекст и задача для НОВОГО ЧАТА (ML-блок) — handoff владения блоком

> Скопируй весь файл в новый чат ML-блока. Он самодостаточен. ML-блок переезжает в отдельный чат;
> общий лид-чат отвечает за интеграцию и выдаёт направление. Ты владеешь `ml/` — коммить ТОЛЬКО `ml/`.

## Проект
MOEX мульти-стратегийный торговый агент, ветка `change-strategy`. Прибыльный агент = портфель
слабо-коррелированных стратегийных сливов + общий риск-слой. Источник правды:
`docs/ARCHITECTURE_V3.md`, **`docs/RESEARCH_HYPOTHESES.md` (КАНОН-леджер — сверяйся ДО любого research)**,
`ml/CLAUDE.md`. Стек — Python; окружение ML — `ml/.venv-win` (Python 3.14, Windows). Валидация — ТОЛЬКО
deployment-симуляция на свежем forward (обычный walk-forward обманул в V1). Тест-сплит 2025-2026 сожжён.

## Роль ML-блока
Сервинг сигналов сливов + риск-аналитика. **Research по market-neutral закрыт** — ML теперь обслуживает
найденный эдж и риск-слой, не ищет новую геометрию тех же цен.

## ⛔ ЗАКРЫТО — НЕ ПЕРЕОТКРЫВАТЬ
Направление 1H одной бумаги (V1); кросс-секц. ранжирование — цена (H1a/b), новости-заголовки (H2),
макро-тилт (H6); попарная реверсия (H7). Четыре провала market-neutral → робастной market-neutral альфы
на этой вселенной испробованными методами НЕТ. Не крутить H1/H6/H7. Контроль информативности любой новой
фичи — time-shuffle/placebo (forward IC обязан падать под перестановкой во времени).

## ✅ H9 — дивидендный пред-ex run-up (слив S3): НАЙДЕН и ДОВЕДЁН
Первый робастный эдж проекта. Вход ~−12 ТД до record-date, выход ~−2 ТД (перед ex-гэпом), сектор-хедж,
inverse-vol. Доказан по 4 осям (per-year, окно входа, dose-response, placebo), no-lookahead сертифицирован
(129/129), P0 пройден (издержки 4-10× запас, робастность 24/24 — сектор-хедж лучший, ёмкость ~130-190 млн ₽).
**Вся ML-сторона H9 закрыта (шаги 1-5):**
- `ml/src/service/dividend_sleeve.py` — `build_sleeve_signal(panel, calendar, as_of)` → `sleeve_signal` JSON
  (лонги + сектор-хедж-рекомендация). Считает торговые дни через `backend.trading_calendar` (RU-праздники).
- `ml/scripts/predict_dividend_sleeve.py` — serving-CLI (`--as-of`, `--out -`), процессный шов для оркестратора.
- `ml/scripts/dividend_sleeve_monitor.py` — forward-shadow монитор.
- `ml/scripts/h9_shadow_pnl.py` — **realized-P&L shadow-гейт** = измеримый критерий снятия `is_production`.
- `ml/scripts/h9_anchor_sverka.py` — сверка якоря (record vs ex date) PASS.
- Риск-аналитика H4 (vol EWMA) / H5 (режимный гейт Mahalanobis): `ml/src/service/risk_analytics.py`.

## Твоя АКТИВНАЯ работа: довести H9 до прода
1. **Сезонное накопление shadow-трека (главное).** `is_production=false`, потому что shadow-гейт сейчас
   **NOT MET** (forward 2025 тонкий/минус: n=12, net −0.93%, dose-инвертирована — негатив в экстремальных
   доходностях/спец-ситуациях). Июль-2026 даёт 7 событий; по мере их закрытия гонять `h9_shadow_pnl.py`
   (нужны свежие свечи — их обновляет backend EOD-ingest). Гейт MET = ≥25 forward-событий, net>0, %pos>0.5
   → тогда рекомендация на sign-off и снятие `is_production=false`. **Дисциплина: НЕ тюнить на тонком/сожжённом
   forward** (есть гипотеза «кап доходности / исключить возобновления+спецвыплаты» — проверять ТОЛЬКО на
   НОВЫХ накопленных событиях, как research-задачу, а не подгонку).
2. *(опц., гигиена)* импорт календаря в сливе можно выровнять на замороженный `backend.api.trading_days_between`
   (сейчас `backend.trading_calendar` — та же функция через ре-экспорт, работает).
