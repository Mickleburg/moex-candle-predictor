# Контекст и задача для НОВОГО ЧАТА (backend/data блок) — автономный ingest + integrity-гейт

> Скопируй весь файл в новый чат backend-блока. Он самодостаточен. Не трогай `ml/`, `llm/`,
> `risk_manager/`, `execution/` — только `backend/`, `scripts/` (свои новые), `config/`, свои тесты.

## Контекст проекта
MOEX trading agent, ветка `change-strategy`, мульти-стратегийная архитектура V3
(`docs/ARCHITECTURE_V3.md`). Цель сейчас — развернуть **автономного агента на VDS** вокруг первого
робастного эджа (H9 дивидендный run-up). Зонтичный план — `docs/VDS_AUTONOMOUS_PLAN.md` (прочитай
секцию «Суточный цикл» — твои шаги 1 и 3). Весь стек — Python (Go-бэкенд удалён 2026-06-15).

## Твоя роль в суточном цикле
**Шаг 1 (EOD):** докачать сегодняшние свечи 16 имён + market context. **Шаг 3:** data-integrity гейт
(свежесть/дыры/NaN) → при фейле сигналить HALT, чтобы оркестратор не торговал на тухлых данных.
Ты — фундамент: на твоих данных считаются и слив (ML), и хедж (risk_manager).

## Задача
1. **Идемпотентный scheduled ingest-джоб** (`backend/...` Python): по триггеру докачивает ТОЛЬКО
   недостающие свежие бары (инкремент, не перекачка истории), мёржит в `data/raw/`, TZ=МСК. Должен
   быть безопасен к повторному запуску (идемпотентность) и к частичным сбоям сети (ретраи/докачка).
2. **Integrity-гейт** (расширить `check_data_quality.py` или новый модуль): проверки — есть бар за
   последний торговый день; нет дыр в торговые дни; нет NaN/нулевых объёмов в ключевых колонках;
   индексы/контекст синхронны по датам. Результат — машинно-читаемый статус (OK/HALT + причины),
   который оркестратор читает перед торговлей.
3. **Торговый календарь MOEX** (общий ресурс): функция «является ли дата торговым днём / следующий
   торговый день», учитывающая RU-праздники (НЕ только выходные). Источник истины — фактические
   торговые дни IMOEX из панели; для форварда — поддерживаемый список RU-праздников. Вынеси так, чтобы
   ML/agent могли импортировать (ML-слив сейчас RU-holiday-наивен — это устраняем централизованно).
4. *(опц., если решите HTTP)* тонкий сервис под контракты `candle_batch`/market context. Для одного
   VDS достаточно общей файловой/SQLite базы — HTTP не обязателен; реши и зафиксируй.

## Приёмка
- Повторный запуск ingest на одних данных не портит/не дублирует (идемпотентность доказана).
- Integrity-гейт ловит искусственно внесённую дыру/NaN и возвращает HALT с причиной.
- Торговый календарь корректно помечает 1/9 мая, 12 июня как НЕторговые; «вход за N торговых дней»
  совпадает с фактическими барами панели.
- `python -m pytest ml/test_smoke.py` зелёный (не ломать ML); валидация контрактов зелёная, если
  трогал контракты.
