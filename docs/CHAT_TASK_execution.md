## Контекст проекта
MOEX trading agent, ветка `change-strategy`, архитектура V3 (`docs/ARCHITECTURE_V3.md`). Разворачиваем
**автономного агента на VDS** вокруг H9 (дивидендный run-up слив). Зонтичный план —
`docs/VDS_AUTONOMOUS_PLAN.md` (твой шаг 6 в суточном цикле). `execution/` сейчас скаффолд (README,
кода нет). **Live запрещён без явного enable-флага; первый режим — dry-run/paper.**

## Твоя роль в суточном цикле
**Шаг 6 (EOD):** получить целевую книгу от risk_manager (`risk_book`/`risk_decision`), сравнить с
текущими позициями, выставить лимит-ордера на вход/выход по дисциплине H9, вести аудит. Реальных
сделок по умолчанию НЕТ — paper, пока команда не сделает sign-off и не включит live-флаг.

## Что уже готово (входы для тебя)
- **Целевая книга:** risk_manager эмитит `risk_decision`/`risk_book` (пер-имя целевые позиции +
  сектор-хедж). Контракты: `contracts/risk_decision.schema.json`, `contracts/order_request.schema.json`,
  `contracts/portfolio_snapshot.schema.json`. Демо потребления: `risk_manager/scripts/demo_combine_h9.py`.
- **Дисциплина H9 (из research, соблюдать точно):** вход ~**−12 торговых дней** до record-date, выход
  ~**−2 ТД** (ПЕРЕД ex-гэпом — это критично, гэп не ловим). Только LONG-ноги от слива; хедж —
  на уровне книги (сектор-индекс), его тоже исполняешь как позицию. Лоты MOEX (round-lot) —
  округление вниз. Ёмкость слива ~130-190 млн ₽ (см. `ml/scripts/h9_capacity.py`).
- **Торговый календарь** строит backend-чат (RU-праздники) — импортируй его, НЕ дублируй; «−12/−2
  торговых дня» считаются по нему, не по календарным.
- Валидатор контрактов `scripts/validate_contracts.py`.

## Задача
1. **Брокер-адаптер с режимами `dry-run` → `paper` → `live`** (live за явным флагом, выключен по
   умолчанию). Выбери брокер-API (кандидаты: **T-Invest API — есть sandbox, простейший paper-путь**;
   Finam TradeAPI; ALOR OpenAPI; QUIK-коннектор). Sandbox-first рекомендуется. Зафиксируй выбор и
   причину в README.
2. **Реконсиляция:** целевая книга vs фактические позиции → дельта-ордера. Только **limit**-ордера.
3. **Дисциплина входа/выхода:** вход −12 ТД / выход −2 ТД по торговому календарю; лот-округление;
   skip weekend-сессий MOEX (политика: эджа там нет).
4. **Защиты:** дубль-ордер-protection, **kill-switch** (мгновенная остановка/снятие всех ордеров),
   аудит-лог каждого ордера/филла, sanity-лимиты (макс размер/имя).
5. **Сверка paper↔симуляция:** paper-прогон по сезону должен совпасть с бэктест-симуляцией слива.

## Приёмка
- dry-run печатает корректные дельта-ордера из примера `risk_book`, не отправляя ничего.
- paper (sandbox) исполняет вход/выход по дисциплине −12/−2; аудит-лог полон; kill-switch снимает всё.
- Дубль-защита не даёт повторный ордер на тот же интент.
- live-путь существует, но ЗАБЛОКИРОВАН без явного флага; `is_production=false` в артефактах.
- `python -m pytest ml/test_smoke.py` зелёный; валидация контрактов зелёная при изменении контрактов.
