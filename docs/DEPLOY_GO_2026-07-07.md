## First-deploy gotchas (observed 2026-07-09/10 — fold into the runbook)
1. **Tiny VDS (1 vCPU / ~1 GB / no swap).** Add a 2 GB swapfile FIRST or the pip build / EOD cycle OOMs:
   `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile` (+ fstab).
2. **Private repo → read-only SSH deploy key** on the VDS (`ssh-keygen … -f /root/.ssh/moex_deploy`,
   add the `.pub` to GitHub → Deploy keys, `~/.ssh/config` IdentityFile), clone via `git@github.com:…`.
3. **Bind-mount perms:** the image runs as non-root uid **10001**; `chown -R 10001:10001 data` on the
   host or the container can't write `data/raw`. **Re-run after any `git pull` that touches `data/`.**
4. **One-off container commands need `--entrypoint python`** (the image ENTRYPOINT is the agent CLI):
   `docker compose … run --rm --entrypoint python agent -m backend.ingest --backfill --with-futures`.
5. **Seed needs `--with-futures`** — else integrity HALTs on `presence/BR_CONT/1H: no data in store`.
6. **Long commands via `nohup … &` (or tmux)** — a bare foreground command dies on SSH disconnect.
7. **Telegram is BLOCKED from this RU host** (RKN; api.telegram.org unreachable on v4+v6). Set
   `AGENT_ALERT_CHANNEL=stdout` and start ONLY the agent (`up -d agent`); the bot needs an out-of-RU
   proxy. Monitor via SSH (`logs agent`, `run --rm agent status`, `tail data/agent/shadow_pnl.jsonl`).
