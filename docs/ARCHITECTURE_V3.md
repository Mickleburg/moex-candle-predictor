# Архитектура V3 — мульти-стратегийный торговый агент

> Статус: **целевая архитектура (источник правды), ветка `change-strategy`, 2026-06-16.**
> Сменяет V2 (`docs/ARCHITECTURE_V2.md` — оставлен как история исследовательской арки).
> Канонический список работ и закрытых гипотез: `docs/RESEARCH_HYPOTHESES.md`.

## Почему V3 (что узнали в V2)

V2 искал ОДНУ кросс-секционную модель «ранг по относительной силе на `[цена ⊕ новости]`». За три
честных захода направленная альфа **не нашлась** на этой вселенной (см. леджер закрытых гипотез):

- направление 1H одной бумаги — шум (win~40%);
- кросс-секция на чистой цене (H1a/b) — комиссии уничтожают, обученный ранжировщик не проходит гейт;
- недельный LLM-сентимент заголовков (H2) — нет ДИНАМИЧЕСКОГО сигнала (time-shuffle бьёт реальный).

Что осталось РАБОЧИМ: **риск-слой** — прогноз волатильности (H4) и режимный гейт (H5). Он делает
любой лонг безопаснее и срезает крах-просадки, но сам альфу не создаёт.

**Вывод, который задаёт V3:** прибыльный агент на MOEX — это **не один предсказатель направления**, а
**портфель слабо-коррелированных стратегийных сливов**, каждый с собственной экономической причиной
эджа, поверх которых работает общий риск-слой. Отдельные сделки и даже целые сливы уходят в минус;
плюс берётся из агрегата (диверсификация источников эджа) и из контроля риска (избегание крахов,
vol-таргетинг). Альфу ищем там, где её ещё НЕ искали: в **экзогенных причинах** (нефть/FX/события) и в
**конструктивно бета-нейтральных спредах** (пары), а не в новой геометрии тех же цен.

## Целевая схема

```
                ┌─ свечи (12+ бумаг, мульти-TF) ───────────────┐
ДАННЫЕ          ├─ market context: Brent, USDRUB, RGBI, IMOEX ─┤
                └─ news ingestion (лента, e-disclosure/TG) ─────┘
                                   │
ПРИЗНАКИ   quant (цена/технички, кросс-секц. z) ⊕ макро-беты (нефть/FX) ⊕ LLM news-события
                                   │
СТРАТЕГИЙНЫЕ СЛИВЫ (каждый даёт целевые позиции, у каждого СВОЯ причина эджа):
   ┌──────────────────────┬───────────────────────┬────────────────────┬───────────────────┐
   │ S1 Pairs stat-arb     │ S2 Macro tilt          │ S3 Event-driven    │ S4 Risk-managed   │
   │ (market-neutral)      │ (cross-sectional)      │ news overlay       │ beta core (опц.)  │
   │ возврат спреда пар    │ экспортёры↔внутренние  │ дивиденды/байбэк/   │ пассив + inv-vol  │
   │ внутри сектора        │ по нефть×USDRUB        │ отчёт-сюрприз/санкц.│ + режимный гейт   │
   └──────────────────────┴───────────────────────┴────────────────────┴───────────────────┘
                                   │  ← КОМБИНАТОР сливов (нетит позиции, веса по риску)
ПОРТФЕЛЬ   risk_manager: vol-targeting (H4) + режимный гейт (H5) + лимиты (по имени/сектору/гросс)
                                   │              + кап на корреляцию сливов
ИСПОЛНЕНИЕ  execution (dry-run/paper; комиссия и проскальзывание в модели)
                                   │
МОНИТОРИНГ  shadow-логи, P&L-атрибуция ПО СЛИВАМ (видно, кто зарабатывает, кто тянет вниз)
```

## Как агент торгует «в плюс» многими бумагами

Прибыль агрегата, а не каждой сделки. Четыре независимых рычага:

1. **Диверсификация причин эджа.** S1 (возврат спреда) не зависит от направления рынка; S2 (макро)
   зарабатывает на дисперсии экспортёры↔внутренние; S3 (события) — на быстрой реакции; S4 — на бете,
   когда рынок растёт. Их P&L слабо коррелированы → суммарная кривая капитала глаже любой одиночной.
2. **Внутренняя диверсификация сливов.** S1 — много пар, S2/S4 — много имён. Один проигрыш не топит
   слив; работает закон больших чисел на положительном ожидании.
3. **Сайзинг по обратной волатильности (H4).** Ни одно имя/пара не доминирует риском; vol-таргетинг
   держит общий риск книги постоянным.
4. **Режимный гейт (H5).** В структурном сломе (2022-типа) гросс срезается → крупные просадки
   обрезаются. Это превращает «потерять много раз в крах» в «потерять мало».

**Long и short.** S1 нативно long/short (спред = лонг одной ноги, шорт другой, бета снята
конструктивно). S2 — тилт весов (перевес экспортёров / недовес внутренних) или long-short top/bottom.
S3 — двусторонний по знаку события. S4 — long-only с гейтом вместо шорта (шорт на MOEX дорог/ограничен).

**Что НЕ даёт прибыль сам по себе:** ни один слив не обязан быть прибыльным в одиночку каждый период.
Критерий — суммарный forward-P&L книги устойчиво >0 на комиссии. Если слив на forward стабильно тянет
вниз — его вес → 0 (атрибуция по сливам это показывает).

## Операционный цикл (как работает день за днём)

1. **Ingest** — догрузить свечи (12+ имён, мульти-TF), market context (Brent/USDRUB/RGBI/IMOEX), новости.
2. **Features** — собрать `feature_bundle`: quant (past-only z) ⊕ макро-беты ⊕ LLM-события (no-lookahead).
3. **Сигналы сливов** — каждый слив выдаёт целевые позиции (контракт `aggregated_signal`, расширенный
   полем `sleeve`).
4. **Комбинатор** — свести сливы в одну книгу (нетто-позиции, веса по риск-вкладу).
5. **Risk layer** — vol-targeting + режимный гейт + лимиты (по имени/сектору/гросс) → итоговые позиции
   (контракт `risk_analytics`).
6. **Execution** — paper/dry-run, комиссия + проскальзывание смоделированы.
7. **Monitoring** — shadow-лог состояния + P&L-атрибуция по сливам.

## Контракты (расширяем существующие, не ломаем дисциплину JSON)

| Контракт | Роль в V3 |
|---|---|
| `candle_batch` | вход данных (без изменений) |
| `llm_analysis` | новостные СОБЫТИЯ по тикеру/моменту (event_type, surprise, affected, impact, as_of) |
| `feature_bundle` | `[quant ⊕ macro ⊕ news]` на вход сливов (расширить полем `macro_*`) |
| `aggregated_signal` | целевые позиции; **+ поле `sleeve`** (s1_pairs/s2_macro/s3_event/s4_core) |
| `risk_analytics` | vol-прогноз + режим + сайзинг/лимиты для портфельного слоя |

Новые поля добавляем обратносовместимо; весь JSON I/O по-прежнему валидируется схемами в `contracts/`.

## Блоки и их роли в V3

| Блок | Роль |
|------|------|
| `ml/` | research + сервинг сигналов сливов S1/S2 и риск-аналитики (H4/H5). Активный блок. |
| `llm/` | извлекатель новостных СОБЫТИЙ (S3) — структура из тел сообщений, не сентимент заголовков. |
| `backend/` | данные: свечи + market context (Brent/USDRUB/RGBI). Python, под контракты. |
| `risk_manager/` | портфельный слой: комбинатор сливов + vol-targeting + гейт + лимиты. |
| `execution/` | paper/dry-run исполнение, модель комиссии/проскальзывания. |
| `agent/` | orchestrator операционного цикла. |

## Дисциплина (наследуется из V2, НЕ нарушать)

- Валидация **только deployment-симуляцией** на свежем forward, с комиссией. Тест 2025-2026 сожжён.
- **Time-shuffle контроль** для любой фичи: forward IC обязан ПАДАТЬ под перестановкой во времени,
  иначе это статический тикер-байас, не сигнал (см. `xsec_feature_validation` в памяти).
- No-lookahead: цена ≤ as_of; новость по времени ПУБЛИКАЦИИ ≤ as_of.
- `is_production=false` до честного forward-гейта + sign-off.
- Каждый слив проходит свой гейт ОТДЕЛЬНО, прежде чем попасть в книгу.

## Открытые проектные решения

- Точный метод комбинирования сливов (равный риск-вклад vs оптимизация vs гейт по атрибуции).
- Частота ребаланса каждого слива (S1 — дни, S2 — дни/неделя, S3 — событие, S4 — неделя).
- Где живёт комбинатор — `risk_manager` (предпочтительно) vs `agent`.
- Нужно ли расширять вселенную под пары (VTB, FIVE/X5, PLZL, MOEX, AFLT — внутрисекторные пары).
