# Контекст и задача для НОВОГО ЧАТА (LLM/news блок) — forward-фид дивидендов

> Скопируй весь файл в новый чат LLM-блока. Он самодостаточен.

## Контекст проекта (коротко)
MOEX trading agent, ветка `change-strategy`, мульти-стратегийная архитектура V3
(`docs/ARCHITECTURE_V3.md`). ML-блок нашёл первый робастный эдж — **дивидендный пред-ex run-up**
(слив S3): покупаем бумагу за ~**12 торговых дней** до ex-дивидендной (record) даты, продаём перед
отсечкой, хеджируем рынок. Эдж доказан и no-lookahead сертифицирован (по твоим же данным объявлений —
спасибо). Сейчас задача проекта — довести H9 до прода (`docs/H9_PRODUCTION_PLAN.md`).

## Проблема, которую закрываешь
Чтобы войти за 12 ТД до ex-даты, нужно ЗНАТЬ предстоящую ex-дату заранее. MOEX ISS `dividends.json`
публикует только ПОДТВЕРЖДЁННЫЕ record dates и ЗАПАЗДЫВАЕТ (на 2026-06-18 в ISS ещё нет дат 2026).
А рекомендация Совета директоров (где объявляются размер дивиденда и созыв ОСА) появляется на
e-disclosure **за ~37 торговых дней до record date** — это твой источник, и он даёт нам запас времени.

## Задача
Поддерживать **forward-looking фид предстоящих дивидендов** для 16 имён: SBER GAZP LKOH GMKN ROSN
NVTK TATN MGNT MTSS SNGS CHMF ALRS VTBR MAGN NLMK PLZL.

Мониторить НОВЫЕ существенные факты на e-disclosure («о решениях СД» / «о созыве ОСА» с рекомендацией
по дивидендам, затем «о решениях ОСА») и извлекать из ТЕЛА сообщения:
- предполагаемый/утверждённый **размер дивиденда** (на акцию),
- **record date** (дата закрытия реестра) — из решения ОСА или рекомендации, как только известна,
- **board_reco_date** (дата заседания/публикации рекомендации СД),
- статус: `recommended` (СД) → `approved` (ОСА) → `confirmed` (record date зафиксирована).

## Выход
Поддерживаемый CSV **`data/news/dividend_calendar_upcoming.csv`** (твоя зона), колонки:
```
ticker, record_date, ex_date, board_reco_date, agm_date, value, status, source_url, as_of, confidence
```
- `record_date` ISO; `ex_date` ≈ record_date − 1 ТД (если не дана явно — оставь пусто, ML посчитает).
- Только БУДУЩИЕ или недавние события (record_date ≥ сегодня − 30 дней). Историю не дублируй —
  она уже в `data/news/dividend_announcements.csv`.
- Обновляй по мере появления новых раскрытий.

## Зачем именно так / приёмка
ML-блок (монитор слива) будет читать этот CSV вместо лагающего ISS, чтобы планировать входы за 12 ТД.
Приёмка: для каждого предстоящего дивиденда `board_reco_date` известна и ≤ (record_date − 12 ТД)
(иначе войти не успеваем — пометь в notes). Отчитайся: сколько предстоящих событий в фиде, медиана
запаса (board_reco → record−12ТД) в днях.
