# Промпт для LLM-чата — даты объявления дивидендов (для no-lookahead H9)

> Скопируй блок ниже в LLM-чат (он владеет e-disclosure / новостной лентой).

---

**Контекст (от ML-блока).** ML-блок нашёл первый робастный эдж проекта — **дивидендный пред-ex
run-up** (покупаем бумагу за ~12 торговых дней до ex-дивидендной даты, продаём перед ex-гэпом,
market-hedged; net +0.84%/событие, прошёл per-year / окно входа / dose-response / placebo). Чтобы
сертифицировать его как **no-lookahead**, нужно подтвердить, что дивиденд был ПУБЛИЧНО ОБЪЯВЛЕН до
момента нашего входа. Институционально и по форме AAR это так, но нужна точная пер-событийная
проверка по датам объявления — это твоя зона (e-disclosure).

**Что нужно.** Для каждого дивидендного события из `data/raw/dividends.csv` (колонки: `ticker`,
`date`=record date / дата закрытия реестра, `value`, `ccy`) — определить **дату первого публичного
объявления дивиденда**:
- **board_reco_date** (приоритет): дата заседания Совета директоров с рекомендацией по дивидендам
  (или дата публикации соответствующего существенного факта на e-disclosure: «о проведении заседания
  СД» / «о решениях СД» / «о рекомендациях по дивидендам»).
- **agm_date** (если доступно): дата ОСА/ГОСА, утвердившего дивиденд («о решениях ОСА»).

**Вселенная (16 тикеров):** SBER GAZP LKOH GMKN ROSN NVTK TATN MGNT MTSS SNGS CHMF ALRS VTBR MAGN
NLMK PLZL. **Приоритет — события с record date 2020-01 … 2025-12** (их использует бэктест; ~120-130
событий). Более ранние (2013-2019) — по возможности, не критично.

**Источник.** e-disclosure.ru (Интерфакс ЦРКИ): сообщения о существенных фактах эмитента —
«о созыве/проведении общего собрания», «о решениях совета директоров», «о начислении/выплате
дивидендов». Альтернативы: MOEX ISS sitenews, IR-страницы эмитентов. Сопоставляй по эмитенту (INN) и
ближайшему к record date объявлению дивиденда за тот же период.

**Выход:** CSV `data/news/dividend_announcements.csv` (твоя зона; закоммить со своими файлами) с
колонками:
```
ticker, record_date, board_reco_date, agm_date, source_url, confidence, notes
```
- `record_date` — ровно как в `dividends.csv` (для join).
- даты в ISO `YYYY-MM-DD`. Пустое поле — если не нашлось (укажи в notes).
- `confidence` — high/med/low (насколько уверен в сопоставлении объявление↔событие).

**Зачем именно так.** ML-блок выполнит тест: `board_reco_date ≤ entry_date`, где
`entry_date ≈ record_date − 12 торговых дней (≈ −17 календарных)`. Если выполняется для ~всех событий —
no-lookahead подтверждён, слив H9 можно вести к forward-shadow. Поэтому важна дневная точность даты
объявления и корректный матчинг к нужному дивиденду (а не к другому корпоративному событию).

**Дисциплина.** Коммить только свои файлы (`data/news/…`, `llm/…`); не трогай файлы ML-блока. Отчитайся:
сколько событий покрыто, медиана зазора (board_reco_date → record_date) в днях, и сколько событий
имеют объявление ПОЗЖЕ `record_date − 12 ТД` (это потенциальные lookahead-нарушители — их разберём).
